# 检查清单

## 输入门槛

### 正式决策必备项（模拟或课堂提案按用户授权标明缺口继续）

- [ ] **问题定义**：谁、什么场景、遇到什么问题、现在怎么凑合、代价；一句话问题定义里找不到功能名。
  - 不合格信号：输入是"做个 AI XX""把 XX 替掉"这类方案，没有还原成问题。
- [ ] **核心用户**：明确首期为谁做；B 端分清实际使用者、供给方、复核方、结果影响方。
- [ ] **调研证据**：至少 2 个真实用户的原话或实际行为，结论能对上证据。
  - 不合格信号：只有"用户觉得""大家都想要"，或只有问看法的问卷结论。
- [ ] **需求池**：需求有来源、痛点和目标；每条能追溯到调研结论。
- [ ] **要提升的目标**：本次立项最终要推动的业务指标或要解决的结果（如转化、留存、人效）。

### 补充项（缺了可继续，记入数据缺口）

- 定量数据（漏斗、埋点、规模）
- 已有竞品测试或体验记录
- 团队与资源现状（人力、瓶颈团队、可用预算）
- 外部时间锚点（上市、活动、版本日历）
- 合规/法务/数据权限状态
- 类型 B：当前版本状态、已在开发中的需求、依赖其他团队交付的能力

## 唱反调

在成稿前用这段提示词（可另开一次推理）：

```
给出最有说服力的论证，说明为什么这个领域的某个竞争对手会成功、而我们会失败。
请具体到：用户为什么不买账、对手凭什么更快更便宜、我们的差异化为什么站不住、
AI 效果达不到门槛时会发生什么、成本在规模放大后会怎样。
```

把站得住的点写进「风险与停止条件」；若动摇了差异化或三问结论，回到对应步骤重做。

## 成稿自检

- [ ] 决策摘要单独看就能拍板：做不做、为谁、先做什么、投多少、怎么证明、什么时候停。
- [ ] 每个数字都有来源标签（一手/二手/测算/假设），二手附链接。
- [ ] 没有把测算写成结果，没有把相关写成因果。
- [ ] 整体问题概括覆盖主要需求簇且没有功能名；本期问题、用户和场景另行收窄，未选需求仍在完整需求池中。
- [ ] 竞品与替代方式覆盖决策所需类别；关于“竞品做不了”的断言有结构性证据，未验证的优势标为假设。
- [ ] 优先级符合用户约定；P0 构成完整闭环并含必要质量底线，P1/P2 有后移理由。小样本不包装成整体用户频率。
- [ ] MVP 只验证一个假设；"必须做"连回痛点，"明确不做"有理由。
- [ ] AI 的价值、效果门槛、失败兜底、数据与成本均有具体内容；正式汇报未机械照搬课堂问句。
- [ ] 每个效果指标写了任务、样本、判定规则；无基线的写明怎么建立。
- [ ] 人机兜底分工写清，高风险决定不交给 AI。
- [ ] 投入有测算口径，钱按阶段批。
- [ ] 每个阶段都有"不过闸怎么办"；有明确停止条件。
- [ ] 待决策事项有责任人和时间点。
- [ ] 数据与信息缺口如实列出。
- [ ] 符合用户选定的文风。

## 参考案例与修订交付

- [ ] 参考案例只用于信息组织与视觉参考，未挪用其业务数据、人物、预算、日期或结论。
- [ ] 正文有清晰结论和取舍；附录保留完整需求、证据、评分依据及详细分析，引用可追溯。
- [ ] 迭代基线沿用用户指定的版本/时间；不能用当前能力反推访谈时状态。
- [ ] 用户已确认的范围和输出格式被沿用，没有重复询问已决定事项。
- [ ] Markdown、HTML、Word 等已承诺格式内容一致，版本及跨章节引用已同步。
- [ ] 原版可恢复；文字、预算和评分改动已核对。文档分页/视觉与网页交互按实际条件验证，未完成的检查如实披露。
