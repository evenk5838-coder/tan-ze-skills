# 多需求报告的修订方法

本文只保留通用方法，不包含产品案例、访谈原话、业务参数、个人工作记录或本机文件位置。

## 整体问题与本期范围

先让整体问题覆盖证据支持的主要需求簇，再说明本期选中的用户、场景和核心闭环。聚焦第一版时，不把暂未纳入的真实问题从背景和需求池里删除。

## 方法与成稿的分工

分析框架帮助检查依据与取舍，报告目录帮助读者决策。正式报告中，将课堂式问句改为用户价值、质量要求、实施可行性、风险和运行成本等陈述；教学任务按用户要求保留方法解释。

## 参考文档的使用

识别参考文档的信息顺序、正文与附录分工及视觉组织，再按当前项目重组。可以借鉴结构，不迁移其用户、商业数据、人员、预算、日期和产品结论。

## 修订与交付

保留可恢复的原版，记录本轮修订范围，更新跨章节引用、评分口径和计算结果。完整需求、证据和详细分析可放入附录；正文优先交代结论、取舍、资源与停止条件。同步更新已经承诺的交付格式。

文件保存位置由当前用户或项目约定决定。只报告实际完成的验证，静态检查不等于浏览器行为验证，技术可行也不等于真实用户效果。
