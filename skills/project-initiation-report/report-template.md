# 立项报告模板

这是默认内容框架，可按用户参考案例重组、合并章节或移动到附录，保留决策所需的信息即可。`【A】` 仅 0→1 使用，`【B】` 仅迭代规划使用。括号和问句是作者的检查提示，正式报告不必照搬。

```markdown
# <项目名> 立项报告

> Owner：<姓名/角色> · 日期：<YYYY-MM-DD> · 版本：v0.x · 结论：做 / 有条件做 / 先不做

## 00 决策摘要（只看这一页也能拍板）

| 决策问题 | 结论 |
|---|---|
| 为什么做 | 整体问题概括 + 最关键证据（没有可靠数字时用可追溯行为或原话） |
| 先为谁做 | 首期用户与场景；明确不覆盖谁 |
| 先做什么 | 第一版要跑通的核心闭环 |
| 如何证明有效 | 首期验收指标（过程指标为主），不作硬验收的指标写明 |
| 投入什么 | 人 × 周期 + 调用/数据成本，分阶段审批 |
| 主要风险 | 3–5 条，每条对应闸门或降级方案 |
| 什么时候停 | 停止条件 |

**立项建议**：<做 / 有条件做（条件、试点范围、AI 的权限边界）/ 先不做（原因与重启条件）>

## 01 背景与问题（为什么现在做）

- 整体问题概括（不含功能名）：覆盖主要需求簇，可用一句话总括再分组展开，不因首版范围而删去其他有证据的问题
- 本期问题与边界：从整体需求中选择首期用户、场景和要验证的核心问题，与整体问题分开表述
- 要推动的目标与逻辑链：目标 = 因素 × 因素，问题出在哪一段
- 【B】现状漏斗/数据，每段流失对应哪个问题
- 为什么是现在：时间窗口、技术变化、外部锚点

## 02 用户与场景（谁 · 多疼 · 证据）

- 核心用户画像：他知道什么、在乎什么、什么时候用、因为什么卡住
- 用户角色关系（B 端：使用者 / 供给方 / 复核方 / 结果影响方）
- 关键场景与现在怎么凑合
- 调研证据：结论 + 原话/行为/数据，标来源
- 【B】改完之后的目标体验路径：今天的样子 → 要做到的样子 → 怎么衡量

## 03 市场与竞品（机会在哪 · 凭什么是我们）

- 分析目的
- 四类竞品表
- 分层对比表（标【推测】的部分）
- 关键洞察（对手把钱押在哪、用户为什么买单）
- 差异化判断：核心用户、在乎的价值、现有替代方式、可验证的优势；缺少结构性证据时写差异化假设

## 04 目标与成功指标（怎么算做成）

| 指标 | 类型（过程/结果） | 口径（任务·样本·判定） | 现状 | 目标 | 依据 |
|---|---|---|---|---|---|

- 无基线的指标写建立方式
- 不在本期给出的目标（如收入/转化）写明原因与何时再定

## 05 方案与第一版范围（做什么 · 明确不做什么）

- 【B】取舍原则（每条附"怎么判断"）
- 完整需求清单及优先级：来源 → 痛点/目标 → 能力 → 功能 → 优先级；Kano 和价值 × 成本是判断工具，未经问卷或定量验证的分类/分数标【假设】
- 如采用权重评分，列出维度、权重、评分口径、依据与成本；分数不能代替闭环、依赖和质量底线判断
- 【B】需求按专题/承接方拆分，标注是否占瓶颈团队
- MVP 范围表

| 要验证的假设 | |
|---|---|
| 必须做 | 每条连回痛点 |
| 明确不做 | 每条写理由 |
| 以后再说 | |
| 怎么算验证通过 | 可量化 + 时间 |

- AI 方案要点（用报告语言，不写到 PRD 粒度）：
  - 能力选择与适用边界：AI 带来的具体价值、规则/静态方案对照、已有能力的复用
  - 效果与验收要求：独立评测任务、基线、门槛、质量与性能
  - 失败处理与责任：AI / 规则 / 人的分工、拒绝或撤销机制、升级处理条件
  - 数据与运行成本：来源、负责人、权限、授权状态及成本口径

## 06 投入与计划（人 · 钱 · 时间 · 分阶段）

- 团队与分工
- 成本测算表（人力 / 模型与语音调用 / 数据 / 其他），全部标【测算】与口径
- 分阶段计划与闸门

| 阶段 | 时间 | 先验证什么 | 主要产出 | 不过闸怎么办 |
|---|---|---|---|---|

- 【B】版本节奏表（锚点倒推，锁版/开发/上线日期）与按角色负载表
- 【B】资源不足时的砍需求顺序（L0–L3）

## 07 风险与停止条件（出错谁兜 · 什么情况下停）

| 风险 | 影响 | 预防/降级 | Owner |
|---|---|---|---|

- 反向论证中有依据的风险与替代方案
- 停止条件 / 转向条件（Go / Continue / Pivot / Stop 判据）

## 08 决策待办与数据缺口

| 时间 | 事项 | 内容 | 责任人 |
|---|---|---|---|

- 数据与信息缺口：缺什么、影响什么判断、怎么补

## 附录

- 【B】未纳入本轮的需求（分组 + 不纳入原因）
- 已明确放弃的方向及理由
- 完整竞品评测数据
- 参考文档清单
```
